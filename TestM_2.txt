## 一、数据 / 3D可视化 / 交互状态 三块是如何解耦的

项目通过**分层架构 + 组合式函数（composable）**把三块清晰地拆开：

### 1. 数据层 — `src/data/mockData.ts` + `src/types/index.ts`
- `types/index.ts` 定义了纯数据契约：`Equipment`、`SensorData`、`EquipmentType`、`EquipmentStatus` 等接口，以及常量 `STATUS_COLORS`、`DEFAULT_SCENE_CONFIG`。这些类型**完全不依赖 Vue 和 Three.js**（唯一例外是 `position` 用了 `THREE.Vector3`，但这是值对象，不是渲染对象）。
- `mockData.ts` 只负责产出一组 `Equipment[]`，以及一个 `updateEquipmentSensorData()` 函数。它不知道任何 3D 渲染逻辑，也不知道用户有没有点击什么。

### 2. 3D 可视化层 — `src/composables/useThreeCore.ts` + `useThreeScene.ts` + `useLights.ts` + `useAnimationLoop.ts` + `src/utils/equipmentFactory.ts`
- `useThreeCore` 封装 Three.js 的 renderer / scene / camera / OrbitControls 的创建和销毁，是纯 3D 引擎基础设施。
- `equipmentFactory` 是**工厂模式**的核心——它接收一个 `Equipment` 数据对象，返回一个 `THREE.Object3D`。数据→3D mesh 的映射全部收敛在这里，每种 `EquipmentType` 对应一个创建函数。
- `useThreeScene` 是"胶水层"：它把 core / lights / equipmentState / animationLoop 四个 composable 编排在一起，但自身不包含业务逻辑。`addEquipmentToScene()` 遍历 `equipmentList`，逐个调 `equipmentFactory.createEquipment()`，然后把 mesh 挂到 scene 上，同时**回写** `equipment.mesh = mesh`——这是数据和 3D 对象之间唯一的桥梁。
- `useLights`、`useAnimationLoop` 各自只管灯和帧循环，互不干扰。

### 3. 交互状态层 — `src/composables/useEquipmentState.ts` + Vue 组件
- `useEquipmentState` 管理着 `equipmentList`（reactive）、`selectedEquipment`（当前选中）、`alarmEquipment`（computed，筛选 isAlarming 的设备）。它提供 `selectEquipment()`、`getEquipmentByMesh()`、`updateEquipmentSensorData()` 等方法。这个 composable **不知道 Three.js 的存在**，它只操作数据。
- `FactoryVisualization.vue` 中的 `handleMouseClick` 是交互入口：用 Raycaster 命中 mesh 后，调 `getEquipmentByMesh()` 反查数据对象，再调 `selectEquipment()` 切换选中状态。3D 点击事件→数据状态变更 这条链路被约束在一个函数里。
- `ControlPanel.vue` 和 `EquipmentInfoPanel.vue` 是纯展示组件，只通过 props / emits 和父组件通信，完全不接触 3D。

**解耦的本质**：数据层只产出 `Equipment[]`；可视化层通过工厂函数把数据转成 mesh；交互层通过 reactive state 管选中/报警，用 raycaster 做 mesh→数据反查。三块之间通过类型接口和 composable 返回值连接，没有循环依赖。

## 二、新增一种设备类型（如"自动输送带" conveyor）需要改动的文件，按顺序

| 顺序 | 文件 | 做什么 |
|------|------|--------|
| 1 | `src/types/index.ts` | 在 `EquipmentType` 联合类型中新增 `'conveyor'` |
| 2 | `src/data/mockData.ts` | 在 `factoryEquipment` 数组中添加一条 `type: 'conveyor'` 的设备数据，补充 position / sensorData / description 等 |
| 3 | `src/utils/equipmentFactory.ts` | 在工厂的创建映射中新增 `conveyor` 分支，编写输送带的 3D 建模逻辑（比如用 `BoxGeometry` 做带体 + 旋转的圆柱做滚筒），设置运行/停止/故障三种材质颜色 |
| 4 | `src/components/ControlPanel.vue` | 在图例区域（legend-grid）中增加输送带的图标项 |
| 5 | `src/components/EquipmentInfoPanel.vue` | 在 `typeText` 的 `typeMap` 中增加 `conveyor: '自动输送带'` 映射 |

以上就是从类型定义 → 数据 → 3D 建模 → UI 展示的全链路。不需要动任何 composable，因为 `useThreeScene` 遍历 `equipmentList` 时是无差别调用 `createEquipment()` 的，`useEquipmentState` 也只依赖 `Equipment` 接口，不需要知道具体类型。
